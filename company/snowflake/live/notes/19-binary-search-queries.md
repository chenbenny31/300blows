## 19. 二分查找与大量重复查询（A04 · LC 704；LC 34 / 35 边界原型）
**证据：** New Grad；平台标签；Phone Screen；P0（J10556）

**本文件合同：**
- 输入为升序 `int` 数组（可含重复、可为空），返回目标下标，不存在返回 -1。
- `search`（LC 704）：有重复值时返回任意一个匹配下标。
- `searchLeftmost`：有重复值时返回最左匹配下标（lower bound 后确认）。
- 数组静态，查询之间不修改；文件只实现单次查询，重复查询优化见 Follow-up。

**先问面试官：**
- 有没有重复值？有的话返回任意、最左还是最右下标？
- 找不到返回 -1，还是插入位置（LC 35）？
- 数组是否静态？查询之间会插入 / 删除吗？
- 查询量 Q 与 n 的比例？查询值是否高度重复 / 聚集？值域是稀疏还是稠密？

**思路：** 闭区间版本维护「答案若存在必在 `[lo, hi]`」，每次比较 `nums[mid]` 丢掉一半，`lo > hi` 时区间为空即不存在。lower bound 维护「第一个 `>= target` 的位置在 `[lo, hi]`」，`hi` 初值为 n 表示可能全小于 target；`nums[mid] < target` 时 mid 及左侧都排除，否则 mid 可能是答案保留在区间里；结束后 `lo` 就是第一个 `>= target` 的位置，再判是否等于 target。`mid = lo + (hi - lo) / 2` 防止下标相加溢出。

**复杂度：** n = 数组长度，Q = 查询次数，D = 不同值个数。
- `search`：T O(log n)，S O(1)。
- `searchLeftmost`：T O(log n)，S O(1)。

**Follow-up：**
- 已实现 `searchLeftmost`（最左下标）：重复值时 LC 704 的答案不唯一，面试里先确认合同。
- 大量重复查询，数组静态：预处理 `unordered_map<int,int> value -> 第一个下标`（顺序扫描，用 `emplace` / `count` 保留首次出现），O(n) 建表、O(D) 空间，每次查询 O(1) 均摊。
- 查询值重复但不想全量建表：memo cache，只缓存查过的值（含未命中的 -1），空间 O(查过的不同值)；可用 LRU 限制大小。
- 值域稠密且小（例如 0..1e6）：用 `vector<int> firstIndex(range, -1)` 代替哈希表，常数更小。
- 有更新：哈希表要随插入 / 删除调整下标（整体后移 O(n)）；更新频繁时改用平衡树或只维护排序数组 + 二分，不再预处理。
- 查询本身是有序批量：双指针一次扫描回答全部，O(n + Q)。

**易错点：**
- 混用区间写法：`hi = n` 却写 `while (lo <= hi)` 会读 `nums[n]` 越界；`hi = n - 1` 却写 `hi = mid` 会死循环。
- 求最左下标时找到就返回 `mid`：`{1,2,2,2,2,3}` 找 2 会返回 2 而不是 1。
- lower bound 结束后不检查 `lo < n` 就读 `nums[lo]`：目标大于所有值时越界。
- 空数组：`hi = n - 1 = -1` 必须是 `int`，用 `size_t` 会下溢成巨大值。
