## 32. 旋转有序数组最小值（B18 · LC 153；追问 LC 154）
**证据：** 职级未确认；平台 Phone Screen（P0）
**本文件合同：**
- `nums` 非空；`findMin` 假设元素严格递增后旋转（无重复）。
- `findMin2` 允许重复，返回最小值（只返回值，不保证返回旋转点下标）。
- 未旋转（旋转 0 次或 n 次）也合法，返回 `nums[0]`。
- 取中点用 `lo + (hi - lo) / 2`，元素可为任意 `int`（只比较，不做加减）。

**先问面试官：**
- 数组一定非空吗？空数组返回什么？
- 有没有重复元素（决定能否保证 O(log n)）？
- 要返回最小值还是它的下标（旋转次数）？
- 可能完全没旋转吗？

**思路：** 不变量：最小值始终在 `[lo, hi]` 内。比较 `nums[mid]` 与 `nums[hi]`：若 `nums[mid] > nums[hi]`，断点在 mid 右边，`lo = mid + 1`；否则 `mid..hi` 有序，最小值在 `lo..mid`，`hi = mid`（mid 本身可能是最小，不能 `-1`）。和 `nums[hi]` 比较能统一处理"未旋转"；和 `nums[lo]` 比较则需要特判。有重复时 `nums[mid] == nums[hi]` 无法判断方向，但 mid 上有一份相同的值，删掉 hi 不会丢失最小值，所以 `hi--`。

**复杂度：** `findMin`：T O(log n)，S O(1)。`findMin2`：T 平均 O(log n)，最坏 O(n)（如全相等或 `[1,1,1,0,1,1]` 类），S O(1)。

**Follow-up：**
- 允许重复（已实现：`findMin2`）：要明确说最坏 O(n)，因为全相等时任何算法都得看过所有元素才能确认没有更小值。
- 返回旋转次数：LC 153 版本返回 `lo` 即可；有重复时需要找"第一个"最小值下标，`hi--` 前若 `nums[hi-1] > nums[hi]` 则 hi 就是答案。
- 在旋转数组中查找 target（LC 33 / 81）：先判哪半边有序，再看 target 是否落在有序半边。

**易错点：**
- `hi = mid - 1`：会跳过恰好在 mid 的最小值。
- 与 `nums[lo]` 比较却不处理未旋转的情况，`[1,2,3]`、`[11,13,15,17]` 出错。
- 循环条件写成 `lo <= hi` 配 `hi = mid`，死循环。
- 有重复时照搬 153 写法，`[3,3,1,3]` 返回 3。
