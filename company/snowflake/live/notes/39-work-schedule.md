## 39. 补齐七天工时的全部日程（B13 · 无直接 LC；39 / 216 回溯原型）
**证据：** 职级／环节未确认；不能断言是 VO；可能被用于不同 coding 环节（P1）
**本文件合同：**
- pattern 恰好 7 个字符，每个是 `'0'..'9'` 或 `'?'`；`0 <= dayHours <= 9`，填进去仍是一位数。
- 固定数字原样保留，即使大于 dayHours（不判非法）；只有 `'?'` 受 `0..dayHours` 限制。
- 返回所有总和恰为 workHours 的日程，按字典序；没有方案返回空 vector。
- 没有 `'?'` 时：固定数字之和等于 workHours 返回 `{pattern}`，否则空。

**先问面试官：**
- 固定数字可以大于 dayHours 吗？若可以，是保留还是整个 pattern 非法？
- dayHours 会超过 9 吗（超过就不能一位数表示，输出格式要改）？
- 输出要全部方案（字典序），还是只要个数？
- 无解返回空列表？pattern 长度一定是 7？

**思路：** 先减掉固定天的工时得到 remaining，然后对 `'?'` 位置从左到右回溯，每位从 0 到 dayHours 递增尝试。所有结果等长、固定位相同，所以先填的位置小的方案字典序也小，DFS 的输出顺序就是字典序，无需排序。剪枝：剩下 left 个空位只能放 `[0, left * dayHours]`，remaining 不在区间内立即返回；这保证每个通过剪枝的节点下面至少有一个解。

**复杂度：** T O(7 + A · (m · D + 7))，S O(m) 递归 + O(7A) 输出；m 为 `'?'` 个数（<= 7），D = dayHours，A 为方案数。因为剪枝后每个被访问的节点都至少通向一个解，访问的节点数 <= m · A，每个节点最多试 D + 1 个子节点；无剪枝时最坏 O((D+1)^m)。

**Follow-up：**
- 只要方案个数：同样的回溯改成计数，或者按"前 idx 个空位用了 s 小时"做计数 DP，O(m · W · D)，W = workHours（本轮预期无 DP，口述即可）。
- 每周天数 / dayHours 不再是常数：把 7 换成 `pattern.size()`；dayHours > 9 时输出要改成 `vector<int>` 或用分隔符。
- 输出规模：方案数可达 C(remaining + m - 1, m - 1) 量级，复杂度必须带上 A，不能只说 O((D+1)^m)。

**易错点：**
- 循环只写 `h <= remaining`，忘了 `h <= dayHours`，会产生 `"0300000"` 这样超出单日上限的方案。
- 剪枝只判 `remaining < 0`，没判 `remaining > left * dayHours`，正确性不受影响但会大量无效搜索。
- 先生成再 `std::sort`：多余，并且掩盖了"递增顺序 = 字典序"这个论证。
- 用 `pattern[i] - '0'` 时把 `'?'` 也减了；或者固定数字超过 dayHours 时误判为无解。
