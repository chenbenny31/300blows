## 23. Top K 累计销量榜（B12 · 无直接 LC；347、692 为部分原型）
**证据：** 职级／环节未确认；Hack2Hire 导出（A26-C03）。P0。
**本文件合同：**
- 对象保存历史累计销量；每次 `bestSellers` 先把本批 `counts[i]` 加到 `books[i]`，再查询。
- 本批出现重复书名时逐条累加；`counts` 允许 0 与负数（退货），累计值用 `long long`。
- 出现过的书都参与排名，包括累计为 0 的书。
- 排序：累计销量降序，同销量书名字典序升序；返回 `min(k, 不同书数)` 个，`k <= 0` 返回空。
- 假设 `books.size() == counts.size()`。

**先问面试官：**
- 本批同一本书出现多次怎么处理？counts 会是 0 或负数吗？
- k 为 0 或大于书数时返回什么？
- 调用频率：查询远多于更新，还是每次批量都很大？（决定维护有序集合还是查询时再排）
- 累计值上限是否超过 int？

**思路：** 方法一维护 `unordered_map` 总量 + `set<(-total, name)>` 排名；更新一本书时先按旧总量删掉旧条目，再插入新条目，set 的首部就是榜首，取前 k 个。set 的键必须包含它排序所需的全部信息，不能让比较器去读可变的 map。方法二只维护总量，查询时用大小为 k 的堆：堆里存 `(-total, name)`，最大堆顶正好是当前 k 个中最差的，超过 k 就弹出，最后反转。

**复杂度：** b 为本批长度，U 为不同书数。
- `bestSellers`（有序集合）：T O(b·logU + k)，S O(U)。
- `bestSellers2`（查询时堆）：T O(b + U·logk)，S O(U + k)。

**Follow-up：**
- 已实现 `bestSellers2`：不维护排名的 size-k 堆版本，适合更新多、查询少。
- 只返回本批之后变化的部分 / 查询 top-k 但不更新：拆成 `add(books, counts)` 与 `top(k)` 两个接口。
- 销量为小整数且 k 固定：bucket 计数可做到更低常数，但同分仍需按名排序。
- 并发：一把锁包住 add+query，保证返回的是同一快照。

**易错点：**
- 更新前没删旧的 `(-old, name)`，同一本书在 set 里出现两次（测试 "return drops x to 3"）。
- 累计用 int，两次 2e9 溢出成负数。
- 用 `priority_queue<pair<long long,string>>` 时方向写反：同分时应弹出名字更大的。
- 堆版本忘记 `reverse`，输出从差到好。
