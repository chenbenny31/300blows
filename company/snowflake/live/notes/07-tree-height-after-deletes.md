## 07. N 叉树删除指定列表后的树高（B01 · LC 559 高度原型）
**证据：** 职级未确认；地里两轮 coding（C02）+ 题库记录（J17038、Hack2Hire Limit Tree Height 标题下的正文也是本题）；线上 coding / Phone Screen；P0

**本文件合同：**
- N 叉树，节点值唯一；root 永远不会被删除。
- 删除一个节点时，它的孩子**提升**到它的父节点下（不是删整棵子树）；可以一次删多个，包括连续的祖孙。
- 只返回最终高度，按路径上的**节点数**计；只剩 root 时高度为 1。
- 删除列表里不在树中的值直接忽略。
- `Node` 的 children 按值存（`vector<Node>`），测试直接用初始化列表建树。

**先问面试官：**
- 删除的是节点（孩子提升）还是整棵子树？
- 高度按节点数还是边数？
- root 能不能被删？删了 root 以后怎么办？
- 删除列表是否可能包含不存在的值、重复值？
- 树有多深？要不要担心递归爆栈？

**思路：** 关键观察：「孩子提升」不会改变任何节点的祖先-后代关系，只是把被删的节点从路径上拿掉。所以结果高度 = 所有 root 到叶子的路径中，**未被删除的节点数**的最大值。后序 DFS：子树高度 = 孩子子树高度的最大值 + （自己被删 ? 0 : 1）。不需要真的改树。`height2` 用显式栈自上而下携带「到这里为止存活的节点数」，适合链状深树。

**复杂度：** V = 节点数，D = 删除列表长度，H = 树高。
- `height`：T O(V+D)，S O(D+H)。
- `height2`：T O(V+D)，S O(V+D)。

**Follow-up：**
- B02（P1，伪代码即可）：最少删除多少个节点使高度 ≤ H。沿用提升规则，这是树形 DP，不在无 DP 主线里；能说清「每条路径上的存活节点数 ≤ H」这个约束以及为什么贪心删最深的节点不一定最优即可。
- 要求返回删除后的树：真的重建，DFS 时把被删节点的孩子接到最近的存活祖先上。
- 多次查询不同删除列表：每次 O(V)；若只删一个节点，可以预处理每个节点子树内最长路径。
- 和 LC 1110 区分：那是删除后断成森林。

**易错点：**
- 把被删节点的整棵子树也删了（`delete 3` 应得 3，不是 2）。
- 对被删节点直接 return 0，忽略了提升上来的孩子。
- 高度按边数算，单节点返回 0。
- 每次检查删除列表时线性查找 `vector`，变成 O(V·D)；应先放进 `unordered_set`。
