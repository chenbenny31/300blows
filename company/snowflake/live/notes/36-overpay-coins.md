## 36. 允许多付找零的最少总硬币数（A10 · 无直接 LC，LC 322 仅为普通找零原型）
**证据：** New Grad；用户贴的平台标签；Phone Screen（P1）
**本文件合同：**
- 面额固定 `{1, 5, 10, 50, 100, 200}`，双方硬币都无限；`0 <= n <= 1e9`（`n + 1000` 不溢出 `int`）。
- 付出金额 p ≥ n，找回 p − n，两边都用同一套面额；代价 = 付出枚数 + 找回枚数。
- 对这套面额，贪心（从大到小取）对任意金额给出最少枚数（canonical 系统）；该结论在测试里用 DP 验证到 2100，**不进入解法代码**。
- 答案 = min over 找零 c ∈ [0, 200) of `greedy(n + c) + greedy(c)`。

**先问面试官：**
- 面额固定还是作为输入（输入的话贪心不一定对，需要先判断/改用 DP）？
- 双方硬币是否无限？收银方是否一定有零钱可找？
- 代价是"付出 + 找回"的总枚数，还是只算付出的？
- n 的范围（是否可能为 0、很大）？

**思路：** 付 p、找 c = p − n 时，两边相互独立，各自的最少枚数就是 `greedy(p)`、`greedy(c)`，所以只需枚举 c。**上界证明：** 若 c ≥ 200，则 p = n + c ≥ 200，贪心表示里 p 和 c 各含至少一枚 200；两边各拿掉一枚 200，得到付 p − 200（仍 ≥ n）、找 c − 200 的方案，代价至少少 2（`greedy(x − 200) ≤ greedy(x) − 1`）。因此最优方案必有 c < 200，枚举 `[0, 200)` 精确无遗漏。（实测最优找零最多只有二三十，但面试中给出可证明的 200 即可，常数仍是 O(1)。）贪心正确性：面额构成整除链（5=5×1，10=2×5，50=5×10，100=2×50，200=2×100），整除链面额系统的贪心总是最优；口头也可补一句 Kozen–Zaks：若贪心有反例，最小反例小于最大两面额之和（300），测试里的 DP 覆盖到 2100。

**复杂度：** K = 面额种数（6）。`minTotalCoins`：T O(200·K) = O(1)，S O(1)。`minTotalCoins2(n, M)`：T O(M·K)，S O(1)。测试中的 DP：T O(A·K)，S O(A)，A = 检查到的最大金额。

**Follow-up：**
- 更宽范围的枚举（已实现：`minTotalCoins2`，测试中用 1000 的范围交叉验证 200 上界）。
- 面额作为输入（可能非 canonical，如 `{1, 3, 4}`）：贪心不再可靠，要对 [0, n + 上界] 做完全背包 DP 求 `dp[x]`，再枚举找零；上界改为最大面额 × 某个系数，需要重新论证（同样的"两边各去掉一枚最大面额"论证要求两边的最优表示都含最大面额，一般不成立）。
- 收银台零钱有限：找零变成有界背包，要另定合同。
- 输出具体付哪些、找哪些硬币：记录最优 c，再对 n + c 和 c 各跑一次贪心输出组合（两边不会出现同一面额的硬币，否则可以抵消）。

**易错点：**
- 只考虑精确支付（标准 coin change），`n = 48` 得 8 而不是 3。
- 枚举找零从 1 开始，漏掉精确支付（c = 0），`n = 200` 得 3（付 200+1 找 1）而不是 1。
- 枚举上界拍脑袋（如只到 n + 5 或 n + 50）且说不出理由；或上界写成 `<= n + 200` 却没解释。
- 断言"必须 DP"：面额固定且 canonical，O(1) 的贪心 + 枚举就够，DP 只用来验证。
