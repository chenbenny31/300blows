## 15. 按独立用户数统计 Top-K 搜索词（A12 · 无直接 LC；排序规则同 LC 692）
**证据：** New Grad；用户贴的平台标签；Phone Screen；P0

**本文件合同：**
- `userId` 是 `int`，`word` 是任意字符串，按原样比较（不做大小写归一）。
- 一个词的分数 = 搜过它的不同用户数；同一用户重复搜同一个词只算一次。
- `getTopK(k)`：分数降序，同分按词字典序升序；k 大于词数时返回全部，k ≤ 0 返回空。
- 没有时间窗口、没有过期（原题未规定）。
- `getTopK` 查询时现排序；`getTopK2` 读写入时维护的有序 set，两者结果相同。

**先问面试官：**
- `recordSearch` 和 `getTopK` 哪个更频繁？k 是固定的还是每次不同？（决定在写时还是读时排序）
- 是否有时间窗口（最近 1 小时）或过期？
- 同分 tie-break 是字典序升序吗？k 大于词数返回什么？
- userId / word 的类型和规模，词是否需要大小写归一？

**思路：** 去重的关键是「word -> 用户集合」，分数是集合大小，只有用户第一次搜这个词时分数才 +1。读时排序：把所有 (分数, 词) 按比较器排序后取前 k。写时维护：有序 set 存 `(-分数, 词)`，`begin()` 就是最优；分数变化时先删旧键再插新键，查询直接顺序取 k 个。

**复杂度：** W = 不同词数，U = 不同 (用户, 词) 对数。
- `recordSearch`：T O(log W) 均摊（哈希查找 + set 删插），S 总计 O(U + W)。
- `getTopK`（现排序）：T O(W log W)，S O(W)；可改为大小为 k 的小顶堆 O(W log k)。
- `getTopK2`（有序 set）：T O(k)，S O(W)（set 本身）。

**Follow-up：**
- 已实现 `getTopK2`：查询频繁时把排序成本挪到写入，每次新增独立用户 O(log W)，查询 O(k)。
- 查询少、写入多：保留 `getTopK`，或用大小为 k 的小顶堆，堆顶是当前第 k 名（比较器方向要反过来想）。
- 时间窗口：每条记录带时间戳，用队列按时间过期；过期时要知道该用户在窗口内是否还有同词记录，所以集合换成「(词, 用户) -> 窗口内次数」，次数归零才让分数 -1。
- 用户规模极大：用户集合换 HyperLogLog 近似计数，此时排名也是近似的，需说明。

**易错点：**
- 直接统计搜索次数：banana 被同一用户搜 3 次会排第一，正确分数是 1。
- 比较器写成 `a.first > b.first || a.second < b.second`：不是严格弱序，同分以外也会被词序干扰。
- 写时维护版本忘记 `erase` 旧键：同一个词在 set 里出现两次，top-k 里重复。
- 循环写 `i < k` 不判 `i < all.size()`：k 大于词数时越界。
