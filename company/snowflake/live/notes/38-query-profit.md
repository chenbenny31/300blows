## 38. 单一类型重复执行的最大利润（B14 · 无直接 LC）
**证据：** 职级／环节未确认；Hack2Hire 导出（P1）
**本文件合同：**
- `time[i] >= 1`、`profit[i] >= 0`（int），`K >= 0`（long long）；返回 `vector<long long>{maxProfit, index}`。
- 只能选一种类型，重复 `floor(K / time[i])` 次；不是混合类型的背包。
- 同分取最小下标（严格 `>` 更新）；没有任何类型能跑一次（含空输入、K = 0）返回 `{0, -1}`。
- 能跑但利润为 0 的类型仍算有效答案，返回 `{0, i}` 而不是 `{0, -1}`。
- 若 profit 可为负：代码返回可行类型中的最大值（可能为负），不会退回 `{0, -1}`；面试时先确认。

**先问面试官：**
- 只能选一种类型重复执行，还是可以混合？
- time 一定为正吗？profit 可以是 0 或负数？
- 同分时取最小下标？"都跑不了"时返回 `{0, -1}`，那"能跑但利润为 0"呢？
- K 与总利润的范围（是否超过 int）？返回 pair 还是两元素数组？

**思路：** 选定类型 i 后最优就是尽量多跑：总利润 `(K / time[i]) * profit[i]`，各类型互相独立，一次线性扫描取最大即可。用 `bestIdx == -1` 表示"还没有可行类型"，这样利润 0 的可行类型也能被正确记录；严格大于保证同分时保留先出现的最小下标。

**复杂度：** T O(n)，S O(1)；n 为类型数。

**Follow-up：**
- 可以混合类型（无限背包）：变成 unbounded knapsack，需要 DP，O(n · K)，K 大时不可行；面试中先确认不是这个版本。
- 很多个预算查询 K1..Kq：每个查询仍需 O(n)，没有明显的单调结构可剪枝（floor 使利润随 time 非单调），直接 O(nq)。
- 为什么比率贪心错：profit/time 最大的类型可能因为整除剩下大量浪费时间（例子：time {3,5}、profit {10,15}、K = 5，比率高的只赚 10）。

**易错点：**
- 用 `best == 0` 判断"没有可行解"，把"能跑但赚 0"误报为 `{0, -1}`。
- 写成 `>=` 更新，同分时返回了更大的下标。
- `K / time[i] * profit[i]` 在 int 里算，K、profit 都到 1e9 时溢出；要让商是 long long 再乘。
- 用 profit/time 比率挑类型（浮点 + 忽略整除）。
