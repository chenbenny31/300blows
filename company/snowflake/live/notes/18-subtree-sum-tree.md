## 18. 构建结构相同的子树和新树（A06 · 无直接 LC；LC 1339 子树和原型，输出不同）
**证据：** New Grad；平台标签；Phone Screen；P0 基础，P1 并发追问（J10558）

**本文件合同：**
- 节点为 `struct Node { int val; vector<Node*> children; }`，N 叉，孩子顺序有意义。
- 返回一棵新分配的树：形状与原树相同，每个新节点值 = 原对应子树所有值之和；原树一个字段都不改。
- 新树由调用方拥有，用 `deleteTree` 释放（测试里每次都释放，ASan/LSan 无泄漏）；新树不与原树共享任何节点。
- 空树（`nullptr`）返回 `nullptr`。子树和假定在 `int` 范围内（有溢出风险时把 `val` 换成 `long long`）。

**先问面试官：**
- 二叉还是 N 叉？节点类型是否给定？值可以为负吗？
- 子树和会不会超过 int？
- 新树的内存谁负责释放？可以返回值类型的树（`vector<Node>` 子节点）吗？
- 树最深多少？递归深度会不会爆栈（决定递归还是显式栈）？
- 原树确定不能改（不能先就地算再拷贝）？

**思路：** 后序遍历：先为每个孩子递归建好新子树，新孩子的值已经是该孩子整棵子树的和，所以父节点新值 = 自身原值 + 各新孩子的值。每个节点只访问一次，只读原树。显式栈版本分两遍：先自顶向下按先序复制形状并记录先序列表（父在子前），再倒序遍历该列表累加，孩子总在父之前完成。

**复杂度：** N = 节点数，H = 树高。
- `build`（递归后序）：T O(N)，S O(N) 新树 + O(H) 递归栈。
- `build2`（显式栈）：T O(N)，S O(N)（新树 + 栈 + 先序列表）。

**Follow-up：**
- 已实现 `build2`：超深树（长链）不爆栈的迭代版本，「超大树 / 迭代」追问的答案。
- 固定 K 个 worker 并发：每个节点的值依赖全部孩子，按「孩子计数器」做自底向上调度：叶子先入任务队列，节点完成后父节点计数器原子减一，降到 0 就入队。关键路径是树高，长链无法并行；任务粒度太小时把小子树整块分给一个 worker 以减少同步。
- 树放不进内存：节点按后序存储在外存中流式处理，栈上只保留当前路径的部分和。
- 只要子树和不要新树：直接返回 `unordered_map<const Node*, long long>` 或原地写到副字段，但本题明确要求新树。

**易错点：**
- 新树直接复用原树的 children 指针（`copy->children = root->children`）：原树被修改，释放时还会 double free。
- 父节点值用「原孩子的值」相加而不是「新孩子的值（子树和）」：只算了两层。
- 每个节点重新遍历整棵子树求和：长链上退化为 O(N²)。
- 用 `new` 建树却不释放，或测试树也用 `new`：ASan 报泄漏；测试输入放栈上，只有输出用 `new` 并 `deleteTree`。
